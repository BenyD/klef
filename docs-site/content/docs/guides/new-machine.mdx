---
title: Restoring on a new Mac
description: Bring every linked repo's env files back onto a fresh or reset machine with klef restore.
---

Because each repo commits its `.klef.json`, a new machine only needs your repos and one Klef command.

## Steps

1. **Install Node.js** 22.18 or newer, then the CLI:

   ```bash
   npm install -g @klefsh/cli
   ```

2. **Clone your repos** as usual, for example under `~/Developer`.

3. **Sign in and unlock.** This opens your browser to approve the machine. Leave **Also unlock the CLI on this device** ticked and confirm with your passkey or passphrase there, so nothing asks again:

   ```bash
   klef login
   ```

   If you approved without unlocking, run `klef unlock` once instead.

4. **Restore** every linked checkout under a directory:

   ```bash
   klef restore ~/Developer
   ```

## What restore does

`restore` walks the directory for `.klef.json` files and lists every checkout it found with the vault project it asks for. It decrypts nothing until you confirm. A cloned repo can name any workspace and project, so look at the list before you say yes.

Then it pulls each checkout's files. Restore **only pulls**:

- A file that is missing locally is written from the vault, with mode `0600`.
- A file that already exists and differs from the vault is left alone and named in the output. Settle it with `klef sync` in that checkout; restore ends with that command for each one, and exits 5 so a script can tell.

That makes restore safe to run again, and means a stale checkout can never overwrite a good version in the vault. `klef restore ~/Developer --yes` skips the confirmation, once you have looked at the list.

## On a machine without a browser

`klef login --paste` signs in with an access token you create in Settings, Security, Access tokens, instead of opening a browser. The token is read from the terminal, not from a flag.

## On Windows

The CLI runs on Windows, and unlocking at login works there too: the key is kept in the Windows Credential Manager. Only the time-limited `klef unlock --for` needs the unlock agent, which Windows does not have yet.
