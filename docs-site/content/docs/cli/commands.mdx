## Get started

### klef setup

Runs every step a repo needs and skips the ones already done, so it is safe to rerun: sign in, link this directory to a project, write instructions for Claude Code and Cursor, unlock, and pull the files that are not on disk yet. It ends with a names-only `klef audit` of the deploy platforms set up here, as one line of counts per scope; a platform whose CLI is missing or signed out is left out.

```bash
klef setup [claude|cursor|claude-md|agents|all] [flags]
```

Naming targets only writes the agent instructions: a Claude Code skill (`claude`), a Cursor rule (`cursor`), a block in `CLAUDE.md` (`claude-md`) or `AGENTS.md` (`agents`). See [Using Klef with Claude Code and Cursor](/docs/guides/coding-agents/).

| Flag | Does |
| --- | --- |
| `--workspace <name>` | Link to a project in this workspace |
| `--project <name>` | Link to this project, without the menu |
| `--global` | Install the Claude Code skill for every project, in `~/.claude` |
| `--paste` | Sign in by pasting a token instead of the browser |

```bash
klef setup                               # everything, step by step
klef setup --project lensdrop --yes      # no menu and no questions, for an agent
klef setup claude cursor                 # only (re)write the agent instructions
```

Without a terminal it stops at each choice: `confirmation_required` with `--workspace`/`--project` to rerun with when the project is ambiguous, or the same command with `--yes` before writing agent files, and `locked` with `klef unlock` when pulling needs the passphrase.

JSON `data`: `{ signedIn, email, linked: { workspace, project, files }, agentFiles: [ { path, action } ], pulled: [ path ] }`. Run with targets, it is `{ agentFiles }`. `action` is `create`, `update`, `unchanged` or `conflict` (a file klef did not write, left alone).

### klef login

Shows a code, opens klef.sh to approve it, and waits. On the approval page, **Also unlock the CLI on this device** (ticked by default) asks once for your passkey or passphrase and sends the vault key to this terminal, sealed so only it can open it. The CLI keeps that key in the OS keychain, so pull, push and sync never ask for the passphrase on this device. See [Unlocked once per device](/docs/concepts/sessions/#the-cli-unlocked-once-per-device).

The token is stored the same way. On its own it reaches ciphertext and names only: it cannot decrypt anything.

```bash
klef login [flags]
```

| Flag | Does |
| --- | --- |
| `--paste` | Paste a token from Settings instead, for machines with no browser. It is read from the terminal, never a flag |
| `--no-remember` | Never keep the vault key on this device. Persists until `--remember` |
| `--remember` | Keep the vault key on this device again (the default) |

```bash
klef login                  # approve in the browser, and unlock this device
klef login --no-remember    # sign in, and keep no key here
```

The code, the link and the waiting go to stderr; the result goes to stdout. A coding agent can run `klef login` too: you approve it in the browser, which is the human step, and the agent can then work without asking you for anything else.

JSON `data`: `{ email, tokenStore: "keychain" | "file", unlocked }`



### klef link

Writes `.klef.json`, which holds names only and is safe to commit. Records `.env.local` and `.env.production` when the project has them, in the vault or in the directory, so `sync`, `pull --all` and `push --all` cover both. With no arguments, lists what can be linked and exits 2. Linking again to the same project changes nothing and says so.

```bash
klef link [workspace] [project] [file] [flags]
```

| Flag | Does |
| --- | --- |
| `--workspace <name>` | The workspace, instead of the first argument |
| `--project <name>` | The project, instead of the second argument |
| `--file <name>` | The default env file, instead of the third argument |

```bash
klef link                      # see what can be linked
klef link Personal lensdrop    # link to a project
```

JSON `data`: `{ workspace, project, file, files: [ { file, path } ], config, changed }`

## Everyday

### klef status

Sign-in, link, lock state and each linked file's sync state, in one call. It reads only and never needs the passphrase. Each file is `in-sync`, `edited-here`, `changed-in-vault`, `both-changed`, `missing-here`, `only-here`, `unknown` (never synced on this machine) or `absent`, worked out from what this machine last synced. Always exits 0.

```bash
klef status [flags]
```

```bash
klef status          # what is going on here
klef status --json   # the same, for a script or an agent
```

`klef status --json` is the one call an agent needs before anything else. Its `next` lists the commands that would move things on.

JSON `data`: `{ version, server, account: { signedIn, email, tokenSource, tokenStatus }, vault: { unlocked, unlockedBy: "remembered" | "agent" | null, keyStore, locksInSeconds, problem }, project: { workspace, project, config } | null, files: [ { file, path, local, inVault, state } ], next: [ { command, description } ] }`

### klef sync

Pull or push each linked file, whichever side changed. A file edited here since it last matched the vault is pushed; one changed in the vault is pulled over the untouched local copy; a file only here is created in the vault. If both changed, or this machine never synced a file that differs, nothing is written and the differing keys are listed (names, never values), exit 5. Pushes ask first. See [Syncing](/docs/guides/sync/).

```bash
klef sync [flags]
```

| Flag | Does |
| --- | --- |
| `--dry-run`, `-n` | Show what would happen, and do none of it |

```bash
klef sync                   # bring everything in line
klef sync --dry-run --json  # what would change, for an agent
```

JSON `data`: `{ dryRun, files: [ { file, path, action, reason, keys? } ] }`. `action` is `in-sync`, `pull`, `push`, `create`, `conflict` or `absent`; `keys` (`{ onlyLocal, onlyVault, changed }`) is there for a conflict. On a conflict the same `data` comes with the error.

### klef pull

Writes the vault's copy of env files here, each at mode `0600`, and reports how many variables each holds; never a value. It overwrites the local copy: `klef sync` is the safe choice when this one may have been edited.

```bash
klef pull [flags]
```

| Flag | Does |
| --- | --- |
| `--file <name>` | One env file in the vault, by name |
| `--path <path>` | Where it lives here (default: its name) |
| `--all` | Every file listed in `.klef.json` |

```bash
klef pull --all                     # every file listed in .klef.json
klef pull --file .env.production    # one file
```

With `--all`, every file is checked before anything is written, so it writes all of them or none.

JSON `data`: `{ files: [ { file, path, variables, version } ] }`

### klef push

Saves local env files to the vault as new versions. It shows what will change in line counts and asks once for all of them. Every earlier version is kept, so a push can be undone in the web app. An empty local file is refused.

```bash
klef push [flags]
```

| Flag | Does |
| --- | --- |
| `--file <name>` | One env file in the vault, by name |
| `--path <path>` | Where it lives here (default: its name) |
| `--all` | Every file listed in `.klef.json` |

```bash
klef push                 # the linked file
klef push --all --yes     # every listed file, no question (after asking the user)
```

JSON `data`: `{ files: [ { file, path, action, variables, added, removed, version } ] }`. `action` is `pushed` or `unchanged`.

### klef diff

Compares local files with the vault, by key, writing nothing. Each differing key is `+` (only here), `-` (only in the vault) or `~` (value differs), by name.

```bash
klef diff [flags]
```

| Flag | Does |
| --- | --- |
| `--file <name>` | One env file in the vault, by name |
| `--path <path>` | Where it lives here (default: its name) |
| `--all` | Every file listed in `.klef.json` |
| `--exit-code` | Exit 10 when there are differences |

```bash
klef diff --all              # which keys differ, and how
klef diff --all --exit-code  # exit 10 if anything differs, for scripts
```

JSON `data`: `{ files: [ { file, path, state, reason, onlyLocal, onlyVault, changed } ] }`. `state` uses the same words as `sync`'s `action`.

### klef run

Runs a command with an env file's variables in its environment, so nothing, and no coding agent, has to open the file to use what is in it: testing an API key, a one-off query against `DATABASE_URL`, starting the app. It reads the local file by default, which needs no unlock; `--from-vault` decrypts the vault's copy instead.

```bash
klef run [flags] -- <command> [args...]
```

| Flag | Does |
| --- | --- |
| `--file <name>` | Which env file (default: the linked one) |
| `--only <KEY,KEY>` | Pass only these variables |
| `--from-vault` | Use the vault's copy instead of the local file (needs the vault unlocked) |

```bash
klef run -- npm run dev                                                   # the app, with .env.local loaded
klef run --only DATABASE_URL -- sh -c 'psql "$DATABASE_URL" -c "select 1"'  # one variable in a query
klef run --file .env.production --from-vault -- node scripts/check.js     # the vault's production values
```

- **Put the command after `--`**, so its flags are its own. Without it, klef reports the first one as an unknown flag.
- **Use `sh -c '...'` with single quotes** for a command that mentions `$NAME`. Otherwise your own shell expands it, to nothing, before klef runs.
- **stdin, stdout, stderr and the exit code pass straight through**, unmasked. klef prints one line of its own on stderr (`klef: 3 variables from .env.local`, none with `-q`) and no value. **The command it runs gets every value and can print any of them**: never run one that echoes a variable, such as `echo`, `env`, `printenv` or a debug log of its config.
- Values are decoded the way dotenv loaders read them: quotes removed, inline ` #` comments dropped. There is no `${VAR}` expansion inside the file. File values take precedence over variables already set in your environment.

`--json` is not supported: the output is the command's own.

## Unlock

### klef unlock

Unlocks this device with the passphrase, for when the browser did not unlock it at login. The passphrase is read from the terminal only, never a flag, pipe or variable, so whatever ran klef cannot supply or see it. The key is then kept in the OS keychain, as after a browser unlock, and later commands never ask.

With `--for`, or with remembering turned off, a background agent holds the key in memory instead and forgets it after that long without use (15 minutes by default). The agent is not available on Windows yet.

```bash
klef unlock [flags]
```

| Flag | Does |
| --- | --- |
| `--for <time>` | Unlock for a while instead, held in memory: `30m`, `8h`, `7d` (at most 7 days) |

```bash
klef unlock          # unlock this device
klef unlock --for 8h # only for a working day
```

Run without a terminal, it stops with `no_terminal` (exit 4): a person has to type the passphrase, or approve `klef login` in the browser. See [Staying signed in and unlocked](/docs/concepts/sessions/).

JSON `data`: `{ unlocked: true, alreadyUnlocked, remembered, locksInSeconds }`

### klef lock

Forgets the key on this device: the one kept in the keychain, and the unlock agent's. Every command then asks for the passphrase until the next unlock or browser sign-in. Locking when already locked is fine and says so. `klef logout` forgets the key too.

```bash
klef lock
```

JSON `data`: `{ locked: true, wasUnlocked }`

## Look around

### klef list

Lists the env files in your vault, names only. Alias: `klef ls`.

```bash
klef list [flags]
klef list --json   # for a script or an agent
```

JSON `data`: `{ files: [ { workspace, project, file, environment, hasVersion } ] }`

### klef audit

Lists the key names Vercel, GitHub Actions or Cloudflare Workers hold that your local files lack, and the reverse. GitHub secrets are compared with what `.github/workflows` references, every Worker in the repo (each `wrangler.json`, `wrangler.jsonc` or `wrangler.toml`) is audited on its own, and an environment with nothing set is one "unused environment" line. Read-only, names only, through your own `vercel`, `gh` and `wrangler` sign-ins. A platform that is not set up here, or whose CLI is missing or signed out, is reported and the rest still run. See [Auditing](/docs/guides/audit/).

```bash
klef audit [vercel|github|cloudflare] [flags]
```

| Flag | Does |
| --- | --- |
| `--exit-code` | Exit 10 when there are differences |

```bash
klef audit                  # every platform set up in this directory
klef audit vercel --json    # one platform, for an agent
```

JSON `data`: `{ targets: [ { platform, environment, label, file, compareTo, worker, status, reason, onlyOnPlatform, onlyLocal, both } ] }`. `compareTo` is `file` (a local env file) or `workflows` (GitHub, where `onlyLocal` is referenced but not set and `onlyOnPlatform` is set but never referenced). `worker` is a Worker's directory. `status` is `ok`, `no-local-file`, `empty` (nothing set there), `skipped` (not set up here) or `unavailable` (the tool failed; `reason` says why).

## New machine

### klef restore

For a new or reset machine: clone your repos, then run this once. It lists every linked checkout under the directory with the vault project each names, and asks before decrypting anything. Then it only pulls. Anything that would push, and any conflict, is left for `klef sync` in that checkout, and the command exits 5 with that `sync` as the next step. See [Restoring on a new Mac](/docs/guides/new-machine/).

```bash
klef restore [dir] [flags]
klef restore ~/Developer   # every linked repo under ~/Developer
```

JSON `data`: `{ root, projects: [ { dir, workspace, project, files: [ { path, action, reason } ] } ], problems: [ { dir, error } ] }`

## Account

### klef logout

Forgets the stored token, and the vault key kept on this device. The token stays valid until you revoke it in the web app (Settings, Security). If `KLEF_TOKEN` is set, klef still signs in with it, and says so.

```bash
klef logout
```

JSON `data`: `{ signedOut, tokenStillInEnvironment }`

## More

### klef completion

Prints a shell completion script. See [Shell completion](/docs/cli/#shell-completion).

```bash
klef completion <bash|zsh|fish>
```

### klef help

Shows help for klef, a command, or a topic: `json`, `exit-codes` or `environment`.

```bash
klef help [command|topic]
klef help pull   # one command
klef help json   # the --json format
```
