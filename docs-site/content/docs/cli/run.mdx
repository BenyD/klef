---
title: klef run
description: Run a command with the vault's variables in its environment, no .env on disk, and every secret value redacted from its output.
---

`klef run` starts a command with an env file's variables in its environment, so nothing, and no coding agent, has to open the file to use what is in it. The command's output passes back through klef, which replaces every value from the file with `[klef:redacted]`.

```bash
klef run -- npm run dev
klef run --only DATABASE_URL -- sh -c 'psql "$DATABASE_URL" -c "select 1"'
klef run --file .env.production --from-vault -- node scripts/check.js
klef run --all -- pnpm test
```

It closes two gaps that `pull` leaves. Once a file is on disk, anything that can read the working directory can read it, including the agent that ran `klef pull`; with `run --from-vault` there need be no file. And a rule against reading the file does nothing about what the app prints: a framework that logs its config, a stack trace with a URL that carries credentials, a test that dumps `process.env`. With `run`, those reach the terminal, the log and the agent as a marker.

## What it does

1. Resolves the linked project from `.klef.json`, like `pull` and `sync`.
2. Reads the linked file (or the one `--file` names, or with `--all` every listed file) from disk, at the path `.klef.json` gives it. With `--from-vault` it fetches the current version from the vault and decrypts it in memory instead; if this device is not unlocked, it stops with `locked` (exit 4) before starting anything, see [Unlocking](/docs/concepts/unlocking/). Reading the local file needs no unlock.
3. Decodes the values the way dotenv loaders do: quotes removed, `\n` expanded inside double quotes, an unquoted value cut at an inline ` #` comment, the last of a repeated key winning. There is no `${VAR}` expansion. With `--all`, files are merged in the order `.klef.json` lists them, and a later file wins a shared key. `--only KEY,KEY` then keeps just the named keys, and fails with `not_found` naming any the file lacks.
4. Starts the command with those variables merged over the current environment. **The file wins**: a variable set in your shell is replaced by the file's value, as if the file had been exported.
5. Forwards the command's stdout and stderr with every value from the file replaced by `[klef:redacted]`, and exits with the command's exit code.

`run` writes nothing. With `--from-vault`, the variables exist in klef's memory and the command's environment, and nowhere else.

## Flags

| Flag | Does |
| --- | --- |
| `--file <name>` | Which env file (default: the linked one) |
| `--all` | Every file listed in `.klef.json`, merged, the later file winning |
| `--only <KEY,KEY>` | Pass only these variables |
| `--from-vault` | Use the vault's copy, decrypted in memory, instead of the local file |
| `--no-redact` | Forward the output as it is, values included. Prints a warning |

Everything after `--` is the command and its arguments, untouched. Flags for klef go before the `--`; flags after it belong to the command. The `--` can be left out when the command's name comes first: `klef run npm run dev` works, since klef stops reading its own flags at the first word that is not one. A command that mentions `$NAME` needs `sh -c '...'` with single quotes, or your own shell expands the name, to nothing, before klef runs.

## Redaction

Every value from the file is replaced in the output, on both streams, wherever it appears: on its own, inside a longer string, or several times on one line. Output is forwarded a line at a time, and a value split across two reads of the pipe is still caught. A line with no newline after it (a prompt, a spinner) is forwarded after a short pause rather than held.

Two kinds of value are left alone, because masking them would wreck the output without protecting anything:

- Values shorter than 5 characters: `1`, `true`, a port number.
- A short list of settings that are never secret, whatever their case: `true`, `false`, `null`, `undefined`, `development`, `production`, `staging`, `test` and `localhost`.

Everything else in the file is treated as secret, including values that are not (a region name, a public URL), because klef cannot tell the two apart and the safe mistake is to mask too much. A redacted value that was not secret costs a glance at the file; a secret value that was not redacted is in a transcript.

Because the output is piped through klef, the command does not see a terminal on its stdout and stderr. Most tools then turn colour off and some change their layout. `--no-redact` gives the command the terminal back, at the cost of the masking, and warns on stderr every time. stdin is always the command's own, so interactive prompts work either way.

## Exit codes and signals

The exit code is the command's: `klef run -- pnpm test` fails when the tests fail. A command ended by a signal exits 128 plus the signal number, as a shell would. Ctrl-C reaches the command from the terminal as usual, and klef waits for it to decide how to stop; SIGTERM and SIGHUP sent to klef alone are passed on to it.

klef's own exit codes apply before the command starts: `not_linked` (6) when there is no `.klef.json`, `not_found` (6) when the local file is not here (the error names `klef pull` and `--from-vault` as the ways out), when the vault has no saved version, when `--only` names a key the file lacks, or when the command itself cannot be found, `locked` (4) when `--from-vault` needs an unlock nobody can give, and a usage error (2) when no command is given.

## JSON

Under `--json` the command's output goes to stderr, redacted, so stdout still carries exactly one object:

```json
{
  "schema": 1,
  "ok": true,
  "command": "run",
  "data": {
    "files": [{ "file": ".env.local", "source": "local", "variables": 12 }],
    "variables": 12,
    "exitCode": 0,
    "redactions": 3,
    "redacted": true
  },
  "warnings": []
}
```

`exitCode` is the command's, and klef exits with it too. `redactions` counts the values replaced, `source` is `local` or `vault`, and `variables` is how many the command was given after `--only`. With `--no-redact`, `redacted` is `false` and the warning is in `warnings`.

## For coding agents

The instructions `klef setup` writes tell the agent to use `klef run -- <command>` instead of reading the file whenever it needs to start the app, run the tests, or use a value (`--only KEY` for one), with `--from-vault` when the file is not on disk, and to pull only when a tool really needs a file. A rule that stops an agent reading `.env` does nothing about what the app prints: a key logged at startup, or in a failing test, lands in the agent's context all the same. `run` is the wrapper that catches it on the way out. See [Using Klef with Claude Code and Cursor](/docs/guides/coding-agents/).

What `run` does not cover: a tool that reads `.env` itself and cannot take variables from the environment (some test runners and ORMs with their own loaders). For those, `klef pull` is still the way, with the file gitignored. And an agent that is told to pass `--no-redact` sees whatever the command prints, so the instructions say never to.
