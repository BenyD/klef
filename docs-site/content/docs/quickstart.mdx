---
title: Quickstart
description: Create a vault, install the CLI, link a project, and pull and push your first env file.
---

This takes about five minutes. You need a browser, and for the CLI, Node.js 22.18 or newer.

## 1. Create your vault

1. Go to [klef.sh](https://klef.sh) and sign in with Google or GitHub.
2. Choose a **master passphrase**: at least 8 characters, and longer is better. It is what encrypts your data, and it is never sent to the server.
3. Save your **recovery key**. It looks like `KLEF-XXXXX-XXXXX-...` and is shown exactly once. Copy it or download it as `klef-recovery-key.txt`, keep it somewhere safe, then tick "I've saved my recovery key."

<Callout type="warn">
The recovery key is the only way back in if you forget the passphrase. If you lose both, nobody can recover your data, because Klef never has the keys.
</Callout>

You land in your vault with a first workspace ready.

## 2. Add a project and a file

1. Create a **project**, for example `my-app`. You can pick its tech stack, which decides the file names Klef suggests.
2. Add a **file** such as `.env.local` and paste your env text into it.
3. Save. If "Review changes before saving" is on, you see a diff first.

Do this before running the CLI: `klef setup` links a repo to a project that already has at least one file in the vault. Once linked, `klef sync` creates any file listed in `.klef.json` that the vault does not have yet.

## 3. Set up the CLI in your repo

From the root of the repository:

```bash
npx @klefsh/cli setup
```

`setup` does everything in one go, and skips whatever is already done:

- **Signs in.** It opens your browser to approve this machine. Check that the short code in the terminal matches the one on the page.
- **Links the repo** to a project in your vault, recording which env files belong to it in `.klef.json`. Commit that file; it holds names only.
- **Offers to teach your coding agents.** It can write a Claude Code skill and a Cursor rule so later sessions know how to sync these files safely. See [Using Klef with Claude Code and Cursor](/docs/guides/coding-agents/).
- **Unlocks** with your passphrase, typed into the terminal.
- **Pulls** the files that are not on disk yet. Each one is written with mode `0600`, and the CLI reports how many variables it wrote, never what they are.

To install the CLI globally instead of going through `npx`:

```bash
npm install -g @klefsh/cli
klef setup
```

## 4. Keep it in sync

After you edit a local file, or change it in the web app:

```bash
klef sync
```

`sync` looks at each linked file and pushes it if you changed it here, or pulls it if it changed in the vault. If both sides changed, it stops, shows which keys differ (names only), and tells you how to settle it. Nothing is written in that case.

You can also move one direction explicitly with `klef pull` and `klef push`.

<Callout type="info">
Run `klef unlock` once at the start of a session. A background agent holds the key in memory for 15 idle minutes, so later commands do not ask for the passphrase again.
</Callout>
